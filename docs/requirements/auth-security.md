# Auth и security

## Назначение

JWT-сессия для SPA без токенов в доступном для JS хранилище; авторизация на каждом backend-запросе.

## Правила и инварианты

### Пользователи

- Публичная регистрация не нужна; пользователи создаются через admin/DB seed.
- Пароли: Argon2 или bcrypt; никогда в открытом виде.
- JWT payload без чувствительных данных.

### Сессия

- Короткоживущий access JWT + refresh-токен с ротацией (rotating refresh).
- Сроки жизни задаются только переменными окружения сервера: `AUTH_ACCESS_TTL`, `AUTH_REFRESH_TTL`, `AUTH_SESSION_TTL`. Числа не зашиты в код. Обязательное соотношение: access < refresh ≤ session. Конфигурация, которая его нарушает, не даёт серверу стартовать.
- Оба — только в `HttpOnly`, `Secure`, `SameSite=Strict` cookies (`Secure` можно выключить только для локальной разработки по HTTP).
- JS на фронтенде не читает и не сохраняет токены; идентичность пользователя восстанавливается через `GET /auth/me`.
- `POST /auth/login`, `POST /auth/refresh` (с ротацией refresh-токена), `POST /auth/logout`.
- Refresh-токен непрозрачный (opaque), в PostgreSQL хранится только хеш; повторное использование после ротации → отзыв сессии.
- CSRF: проверка `Origin` из allow-листа + CORS с credentials на небезопасных запросах.

### Безопасность / authz

- Не хранить пароль / JWT secret / учётные данные БД во frontend.
- Не класть чувствительные финансовые данные в URL.
- Backend всегда проверяет аутентификацию и права доступа; фронтенд не является границей безопасности.
- Любой аутентифицированный пользователь имеет доступ ко всем финансовым данным в едином пространстве; preferences — только у владельца.
- Защита `POST /auth/login` от подбора пароля (задача `login-attempt-limit`). Счётчики неудачных попыток хранятся в PostgreSQL, не в памяти процесса. Лимит: 5 неудач на нормализованный email за 15 минут и 30 неудач на IP за 15 минут. При превышении — `429`, без сообщения о том, существует ли email. Успешный вход сбрасывает счётчик этого email. Ответ на неверный пароль остаётся общим и не говорит, не найден пользователь или неверен пароль.
