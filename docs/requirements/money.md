# Money

## Назначение

Единое decimal-safe представление денег на wire, в domain и в БД.

## Правила и инварианты

- Никогда не использовать JS `number` для денежных расчётов. `0.1 + 0.2` через `number` не является допустимым денежным результатом.
- Абстракция `Money = { amount: string; currency: CurrencyCode }`; `amount` decimal-safe (строка, не float).
- Persist: PostgreSQL `NUMERIC`.
- Арифметика только через `@balance/domain/money`.
- Точность одна на всю систему: 2 знака после запятой. Её не хранят и не настраивают ни по валюте, ни в справочнике. Сумма с большим числом знаков не проходит валидацию; меньшее дополняется нулями до 2 знаков (`1.5` → `1.50`).

### Ввод денег (UI)

- Только дробные значения в decimal-представлении; никакого float.
- Поле ввода принимает не больше 2 знаков после запятой.
- Ввод с клавиатуры должен корректно работать на desktop.
- Некорректные значения не должны проходить валидацию.

## Контракты

- `@balance/dto` типы Money / currency; `@balance/domain/money`

## Вне целей

- Float «для удобства» на фронтенде или бэкенде.
