# Multi-user attribution

## Назначение

Единое финансовое пространство, 1–n пользователей; attribution (атрибуция) на операциях, а не ownership (владение) счетами.

## Правила и инварианты

- Нет отдельных пространств на пользователя, переключателя между ними, модели authz «моё vs общее».
- Кто каким счётом пользуется — социальная договорённость, а не ACL (список прав доступа).
- На финансовых мутациях обязателен минимум `createdBy` (при необходимости `updatedBy`).
- Любой аутентифицированный пользователь читает и меняет все счета, категории и транзакции в пространстве; preferences — только у их владельца (`/users/me/...`).
- Не вводить `Space` / `AccountMember`.
- Несколько финансовых пространств — решение не принято; не строить заранее.

### UX атрибуции

- В списках показывать `createdBy` (и `updatedBy`, где уместно).

## Нужно сделать

- Фильтр списка все / я / выбранные пользователи web не использует. Его снимают с API; показ `createdBy` в списке остаётся. Задача `drop-created-by-list-filter`.
