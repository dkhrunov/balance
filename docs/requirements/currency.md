# Currency

## Назначение

Единый справочник валют в PostgreSQL. Счета, транзакции и `defaultCurrency` ссылаются на него. Список валют не зашит в код приложения.

## Правила и инварианты

### Справочник

- Таблица `currencies`. Колонки: `key` (код ISO 4217, первичный ключ), `symbol` (символ для отображения). Названия валюты и точности в справочнике нет. У всех сумм 2 знака после запятой ([`money.md`](./money.md)).
- Начальные строки, которые создаёт миграция:

| key | symbol |
| --- | ------ |
| RUB | ₽      |
| USD | $      |
| EUR | €      |

- `key` — значение, которое хранят счёт, транзакция и `defaultCurrency`. Новую валюту добавляют строкой в БД.
- Отдельная миграция переводит уже существующие колонки на справочник. Сейчас `accounts.currency_code`, `transactions.currency_code` и `users.default_currency_code` — `text` с проверкой `IN ('RUB', 'USD', 'EUR')`. Миграция сначала создаёт `currencies` и три начальные строки, затем снимает эти проверки и добавляет внешний ключ трёх колонок на `currencies.key`. Тип колонки остаётся строковым кодом: внешний ключ ссылается на `key`, а не на числовой суррогат. Удаление строки справочника, на которую есть счёт, транзакция или пользователь, база отклоняет.
- Создание, изменение и удаление строк справочника — только SQL (миграция или правка в БД). HTTP-методов на запись нет.

### Ссылки

- У пользователя есть `defaultCurrency`: это `key` из справочника и только подсказка при создании счёта.
- Валюта счёта — явный `key` из справочника. После создания счёта она не меняется и не подменяется `defaultCurrency` (см. [`accounts.md`](./accounts.md)).
- Валюта транзакции равна валюте её счёта и тоже является `key` справочника.
- Суммы и аналитика по нескольким валютам — [`analytics.md`](./analytics.md). `ExchangeRate` (базовая и котируемая валюта, курс, timestamp, источник) не пересчитывает историю текущим курсом без явного выбора.

## Контракты

- `@balance/dto/currencies`
- `GET /currencies/version` — `{ version }`. `GET /currencies` — `{ version, items }`. `items`: `{ key, symbol }`, порядок по `key`. `version` — хеш канонического содержимого строк (`key`, `symbol`). Любая правка строки в БД меняет `version`. Оба ответа с `Cache-Control: no-store`, чтобы браузер не подменил сравнение своей HTTP-копией. Записи справочника через API нет.

## Поведение на web

- Своего списка кодов нет. Кэш — `localStorage`, ключ `currency-catalog:v1`, значение `{ version, items }`. Кэш общий на приложение, не на пользователя, и не очищается при выходе. Это справочник, не финансовое состояние.
- Кэш считается отсутствующим, если хранилище недоступно, JSON не читается, нет `version` или `items` пуст либо не той формы.
- Кэш есть: сразу показать его и запросить только `GET /currencies/version`. Версии совпали — справочник не запрашивать. Не совпали — `GET /currencies` и заменить кэш парой из этого ответа (его `version`, не той, что пришла проверкой раньше).
- Кэша нет: сразу `GET /currencies`, без предварительной проверки версии.
- Проверка версии или полная загрузка не удались, кэш есть — оставить кэш. `401` кэш не стирает. Кэша нет и полная загрузка не удалась — формы выбора валюты не подставляют зашитый набор `RUB`/`USD`/`EUR`.
- Одновременно идёт не больше одной проверки версии и не больше одной загрузки справочника. Другая вкладка, записавшая кэш, подхватывается через событие `storage`.
- Символ берётся из строки справочника с нужным `key`. Название валюты в базе не хранится: его даёт `Intl.DisplayNames` для активной локали и этого `key`. Если название или символ получить нельзя, показывается сам `key`.

## Поведение на server

- Чтение справочника доступно аутентифицированному пользователю.
- Проверка валюты счёта, транзакции и `defaultCurrency` идёт по `currencies.key`, не по зашитому списку в коде.
- `POST` / `PUT` / `PATCH` / `DELETE` для справочника отсутствуют.

## Вне целей

- Редактирование справочника из UI.
- Колонка точности у валюты.
- Название валюты в базе.
- Конвертация и валюта отчёта.
