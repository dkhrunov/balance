# Categories

## Назначение

Раздельные категории дохода и расхода в общем финансовом пространстве.

## Правила и инварианты

- Тип: `INCOME` | `EXPENSE`. Задаётся только при создании и дальше не меняется. Обновление принимает имя, иконку и цвет, не тип.
- Имя: 1–120 символов после trim.
- Общее пространство, без владельца. Любой аутентифицированный пользователь может CRUD любую категорию.
- Soft-delete (`deletedAt`) и `version`. Удаление категории, на которую ссылаются транзакции, разрешено. Транзакции сохраняют `categoryId` и по-прежнему показывают имя, иконку и цвет категории. Удалённая категория пропадает из активного списка и не выбирается для новой операции. `categoryId` у истории не обнуляется и транзакции не удаляются вместе с категорией.
- Поля и связи — [`ERD.md`](./ERD.md).

### Иконка

- Колонка `icon`, `text NOT NULL`. Это имя экспорта Carbon-иконки (`Wallet`, `ShoppingCart`), не URL, не SVG и не emoji.
- Длина 1–64 символа. Пробелы по краям не обрезаются: имя сравнивается как есть.
- Создание: поле можно не передавать. Тогда сервер пишет `Wallet`.
- Обновление: поле обязано прийти вместе с именем, цветом и `version`.
- Сервер не сверяет имя с каталогом иконок. Каталог живёт в web: picker предлагает фиксированный набор, тот же, из которого рисуется список.
- Неизвестное имя сервер сохраняет. Web рисует вместо него `Wallet` и не подменяет сохранённое значение.
- Иконка не кодирует тип. Две категории одного типа могут делить одну иконку.
- Где видна: список на `/settings` (иконка строки), выбор категории в форме операции, строка операции в таблице. Рядом всегда имя категории.

### Цвет

Цвет отличает категории в списке и рядом с операцией. На суммы, отчёты и допустимость операции не влияет. Смена цвета меняет вид прошлых операций: у транзакции хранится `categoryId`, не копия цвета.

- Колонка `color`, `text NOT NULL`. Закрытый набор ключей Carbon Tag, нижний регистр, без пробелов. Hex, `rgb` и CSS-переменные не принимаются: один ключ рисуется токеном активной темы (light / dark / system).
- Набор — заливки Tag, которые остаются различимыми в light и dark. `high-contrast` и `outline` не входят: это не оттенок. Порядок в picker:

```text
blue, cyan, teal, green, gray, cool-gray, warm-gray, purple, magenta, red
```

- Дефолт — `blue`.

- Создание: поле можно не передавать. Тогда сервер пишет `blue`. Переданный ключ вне набора — `400`, код `CATEGORY_VALIDATION_FAILED`. Пустая строка и `null` — тот же отказ.
- Обновление: поле обязательно и из того же набора. Тот же код отказа.
- Цвет не уникален и не выводится из типа. Доход не обязан быть зелёным, расход — красным.
- Уже существующие строки: миграция добавляет колонку со значением `blue`. Отдельной раскраски посева нет.
- Подпись цвета для человека берётся из i18n (`en` и `ru`) по ключу, не из базы.
- Где виден: тот же ряд, что и иконка — список на `/settings`, выбор категории, строка операции. Образец цвета не заменяет имя и иконку. У образца есть доступное имя, совпадающее с подписью из i18n.
- В форме создания и правки — выбор одного ключа из набора. На создании выбран `blue`, даже если клиент поле не пришлёт. На правке выбран сохранённый ключ. Неизвестный сохранённый ключ в форме показать нельзя: сервер такой ключ не пишет.

## Контракты

- `@balance/dto/categories`

## Поведение на web

- Список, создание и правка на странице настроек (`/settings`), отдельно для дохода и расхода. В форме создания есть тип; в форме правки типа нет. В обеих формах есть имя, выбор иконки и выбор цвета. Состояния empty/loading/error.

## Поведение на server

- CRUD + soft-delete; обязательна аутентификация; optimistic concurrency. Обновление отклоняет смену типа. Soft-delete не проверяет число ссылающихся транзакций. Проверка `icon` — длина. Проверка `color` — вхождение в набор. Оба отказа — `CATEGORY_VALIDATION_FAILED`.

## Вне целей

- Произвольный цвет вне таблицы ключей.
- Снимок иконки или цвета на строке транзакции.
- Цвет как признак типа или как фильтр списка.

## Нужно сделать

- Колонки `color` нет. В контракте, create/update и ответах категории цвета нет. Форма и списки цвет не показывают. Иконка уже сохраняется и рисуется.
- Имя, иконка и цвет soft-deleted категории не читаются: выборки категорий отсекают `deleted_at`, в транзакции только `categoryId`.
