# ADR-0014: Online desktop product

- **Status:** Accepted
- **Date:** 2026-11-02
- **Deciders:** project
- **Related specs:** `docs/requirements/scope.md`, `docs/requirements/principles.md`
- **Related code:** `apps/web`, `apps/server`

## Контекст

Финансовое состояние должно быть общим для нескольких пользователей. Источник состояния — сервер.

## Решение

- Клиент читает и меняет данные через API. Сервер — единственный источник финансового состояния.
- Не хранить финансовое состояние только в браузере.
- Сохранить инварианты мутаций (ADR-0008, ADR-0009): `operationId`, `version`, tombstone.

## Рассмотренные альтернативы

- **Локальное хранилище как источник финансового состояния** — отвергнуто: ломает общее пространство и конкурентные правки.
- **Выкинуть operationId/version/tombstone** — отвергнуто: нужны online concurrency и идемпотентность.

## Последствия

### Плюсы

- Узкий DoD: клиент работает с API.
- Атрибуция и конфликты версий считаются на сервере.

### Минусы и компромиссы

- Без сети клиент не ведёт учёт.

### Дальнейшие шаги

- Нет.
