# ADR-0002: SQL-миграции и schema_migrations

- **Status:** Accepted
- **Date:** 2026-11-07
- **Deciders:** project
- **Related specs:** `docs/requirements/ERD.md`
- **Related code:** `apps/server/scripts/migrate.mjs`, `apps/server/migrations/`

## Контекст

Схема PostgreSQL меняется вместе с фичами, без ORM. Нужен воспроизводимый порядок применения SQL и запись о том, что уже выполнено на конкретной базе. Иначе повторный запуск создаёт объекты второй раз, а откат не знает, какой файл отменять.

## Решение

- Пара файлов на изменение: `apps/server/migrations/NNN-kebab.up.sql` и `NNN-kebab.down.sql`. `NNN` — следующий номер без пропусков. Имя без суффикса — ключ миграции.
- Журнал — таблица `schema_migrations` (`name` PK, `applied_at`). Её создаёт раннер при старте, не номерной `.up.sql`.
- Применение идёт по возрастанию имени. Уже записанное имя пропускается. Один файл — одна транзакция: SQL, затем `INSERT` в журнал, затем `COMMIT`. Ошибка откатывает и SQL, и запись.
- Откат снимает только последнюю запись журнала (`applied_at`, затем имя) и выполняет её `.down.sql`.
- Два запуска не идут параллельно: перед работой берётся advisory lock.

### Как применять

- Накатить ожидающие: `npm run db:migrate`.
- Откатить последнюю: `npm run db:migrate:down`.
- Уже применённый файл не правят. Следующее изменение схемы — новая пара файлов.
- Подключение берётся из `apps/server/.env` (`DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_USER`, `DATABASE_PASSWORD`, `DATABASE_NAME`).

## Рассмотренные альтернативы

- **Prisma / TypeORM migrations** — тот же отказ, что в ADR-0011: контроль SQL и `NUMERIC` важнее генератора.
- **Flyway, golang-migrate, node-pg-migrate** — отдельный инструмент ради упорядоченных SQL-файлов. Своего раннера достаточно.
- **Ручной SQL без журнала** — нельзя безопасно повторить накат и понять, какая миграция последняя.

## Последствия

### Плюсы

- Схема воспроизводится из репозитория. Повторный `db:migrate` ничего не применяет второй раз.
- Откат одной последней миграции есть, пока `.down.sql` соответствует `.up.sql`.

### Минусы и компромиссы

- Откатывается только последний шаг, не произвольная середина истории.
- Дисциплина парных файлов на авторе миграции: раннер не проверяет, что `.down.sql` реально обратен `.up.sql`.

### Дальнейшие шаги

- Нет.
