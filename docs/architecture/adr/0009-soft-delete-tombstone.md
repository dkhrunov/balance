# ADR-0009: Soft-delete tombstone

- **Status:** Accepted
- **Date:** 2026-11-02
- **Deciders:** project
- **Related specs:** `docs/requirements/idempotency-concurrency.md`
- **Related code:** Account / Category / Transaction `deletedAt`

## Контекст

Общее финансовое пространство, которое видно сразу нескольким пользователям. Физическое удаление скрывает факт удаления от других сессий и ломает историчность операций.

## Решение

Вместо жесткого удаления записей из DB, хранится статус удаления в `deletedAt` (tombstone). Списки и балансы учитывают tombstone.

Нужно для **multi-user consistency**, не как требование для локальной очереди.

## Рассмотренные альтернативы

- **Hard delete** — другие пользователи не видят удаление; риск битых ссылок и «исчезнувших» сумм.
- **Только delete event log без tombstone на entity** — сложнее текущие запросы.

## Последствия

### Плюсы

- Удаление наблюдаемо; ledger остаётся согласованным.
- Простые фильтры `WHERE deleted_at IS NULL`.

### Минусы и компромиссы

- Таблицы растут; политика retention/purge ещё не задана.

### Дальнейшие шаги

- Нет.
